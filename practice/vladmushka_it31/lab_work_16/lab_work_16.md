 Завдання 1. Перевірка початкової кількості записів

Перед імпортом було перевірено структуру таблиці `books` за допомогою команди `.schema books` та підраховано кількість записів:

```sql
SELECT COUNT(*) FROM books;
```

Результат — 8 записів.

Це потрібно для того, щоб знати початкову кількість книг і після імпорту перевірити, скільки нових записів було додано.

 Завдання 3. Імпорт даних через проміжну таблицю

CSV-файл містить 5 стовпців: `title`, `author`, `publication_year`, `genre`, `copies_count`. У таблиці `books` є додатковий стовпець `id`, тому прямий імпорт може спричинити помилку.

Для правильного імпорту було створено проміжну таблицю `books_staging` без стовпця `id`. Дані завантажено командами:

```sql
.mode csv
.import --skip 1 v1_new_rows.csv books_staging
```

Після перевірки дані перенесено до основної таблиці:

```sql
INSERT INTO books (title, author, publication_year, genre, copies_count)
SELECT title, author, publication_year, genre, copies_count
FROM books_staging;
```

Стовпець `id` не вказувався, тому SQLite автоматично присвоїла новим книгам ідентифікатори від 9 до 16.

Після імпорту кількість записів становила 16. Отже, було додано 8 нових книг.

 Завдання 4. Перевірка результатів імпорту

Для перевірки нових записів використано запит:

```sql
SELECT id, title, author
FROM books
WHERE id > 8;
```

Результат показав усі 8 нових книг з ідентифікаторами від 9 до 16.

Після успішного перенесення даних проміжну таблицю видалено:

```sql
DROP TABLE books_staging;
```

Це дозволяє не зберігати непотрібну таблицю та уникнути випадкового повторного перенесення тих самих записів.

 Завдання 5. Перевірка прямого імпорту

Для перевірки було створено окрему копію початкової бази даних `lab_work_16_test.db`.

Після виконання команд:

```sql
.mode csv
.import --skip 1 v1_new_rows.csv books
```

SQLite повідомила про помилки:

- `expected 6 columns but found 5` — у таблиці 6 стовпців, а в CSV лише 5.
- `datatype mismatch` — текстова назва книги потрапляє на місце числового стовпця `id`.

Після перевірки кількості записів у тестовій базі результат становив 8. Жодна нова книга не була додана.

Отже, прямий імпорт у таблицю з додатковим стовпцем `id` не підходить. Правильний спосіб — використання проміжної таблиці.

 Контрольні питання

1. Чому CSV-файл не містить колонку `id`? Що сталося б, якби додати її самостійно з довільними значеннями

Стовпець `id` створюється автоматично базою даних, оскільки він є первинним ключем. Якщо додати довільні значення, можуть виникнути дублікати ідентифікаторів або конфлікти з уже наявними записами. Тому краще дозволити SQLite самостійно призначати ID.

2. Яка роль `DROP TABLE` проміжної таблиці? Чи можна залишити її в базі

`DROP TABLE` видаляє проміжну таблицю після перенесення даних. Залишати її небажано, оскільки під час наступного імпорту можуть накопичуватися старі записи та виникати повторне додавання даних до основної таблиці.

3. Чим підрахунок `COUNT(*)` до й після імпорту кращий за враження, що імпорт спрацював?

`COUNT(*)` дає точну кількість записів у таблиці. До імпорту було 8 записів, після — 16. Різниця становить 8, що підтверджує успішне додавання всіх записів із CSV-файлу. Це надійніше, ніж оцінювати результат лише візуально.
