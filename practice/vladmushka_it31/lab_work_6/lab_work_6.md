Лабораторна робота №6
Тема: Оновлення та видалення даних у базі даних.
Варіант 1 Бібліотека

Завдання 1

Було виконано оновлення запису у таблиці loans. Для книги з ідентифікатором запису 3 було заповнено поле return_date.

Команда:

UPDATE loans
SET return_date = '2026-09-20'
WHERE id = 3;

До оновлення поле return_date для запису з id = 3 було порожнім.

Після виконання команди перевірка:

SELECT * FROM loans WHERE id = 3;

Результат:

3|3|3|2026-09-03|2026-09-20

Отже, дата повернення книги була успішно встановлена.

Завдання 2

Було виконано оновлення кількості примірників книги у таблиці books.

Команда:

UPDATE books
SET copies_count = copies_count + 1
WHERE id = 2;

До оновлення кількість примірників книги «Тигролови» становила 3.

Після виконання команди перевірка:

SELECT * FROM books WHERE id = 2;

Результат:

2|Тигролови|Іван Багряний|1944|Роман|4

Кількість примірників збільшилася з 3 до 4.

UPDATE використовується тому, що змінюється тільки певне значення вже існуючого запису. Видаляти запис і створювати його заново недоцільно, оскільки це може призвести до втрати інших даних, порушення зв'язків та зайвих операцій.

Завдання 3

Перед видаленням було перевірено кількість записів у таблиці loans.

Команда:

SELECT COUNT(*) FROM loans;

Результат:

10

Було видалено один конкретний запис за первинним ключем.

Команда:

DELETE FROM loans
WHERE id = 10;

Після видалення кількість записів було перевірено повторно.

Команда:

SELECT COUNT(*) FROM loans;

Результат:

9

Отже, було видалено саме один запис.

Завдання 4

Для перевірки поведінки зовнішнього ключа було увімкнено контроль зовнішніх ключів:

PRAGMA foreign_keys = ON;

Структуру таблиці loans було перевірено командою:

.schema loans

У таблиці loans зовнішні ключі визначені так:

FOREIGN KEY (book_id) REFERENCES books(id),
FOREIGN KEY (reader_id) REFERENCES readers(id)

Явна дія ON DELETE у структурі таблиці не вказана. Тому використовується стандартна поведінка SQLite — видалення батьківського запису не дозволяється, якщо на нього посилаються записи дочірньої таблиці.

Перед видаленням було перевірено, чи є записи loans, які посилаються на книгу з id = 2:

SELECT * FROM loans WHERE book_id = 2;

Результат:

1|2|1|2026-09-01|2026-09-10
6|2|5|2026-09-06|2026-09-13

Отже, книга з id = 2 має пов'язані записи у таблиці loans.

Було виконано спробу видалення книги:

DELETE FROM books
WHERE id = 2;

Результат:

FOREIGN KEY constraint failed (19)

Видалення не виконалося через наявність пов'язаних записів у таблиці loans.

Після цього було перевірено, чи залишилася книга:

SELECT * FROM books WHERE id = 2;

Результат:

2|Тигролови|Іван Багряний|1944|Роман|4

Отже, запис книги не був видалений.

Висновок

Під час лабораторної роботи було виконано оновлення та видалення даних у базі даних. У таблиці loans було заповнено дату повернення книги, а в таблиці books збільшено кількість примірників книги. Також було видалено один запис із таблиці loans. Під час перевірки зовнішнього ключа було встановлено, що видалення книги, на яку посилаються записи таблиці loans, забороняється. Це підтверджує роботу контролю зовнішніх ключів SQLite.
