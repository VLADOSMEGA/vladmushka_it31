# Практична робота №19
## Міграція бази даних SQLite до PostgreSQL

### 1. Створення таблиць

У PostgreSQL створено три таблиці: `books`, `readers` та `loans`. Для первинних ключів використано `GENERATED ALWAYS AS IDENTITY`, для зв'язків — зовнішні ключі.

### 2. Експорт та імпорт даних

Дані з SQLite експортовано у CSV-файли та імпортовано через pgAdmin 4 у PostgreSQL.

### 3. Перевірка кількості записів

Після імпорту отримано такі результати:

- `books` — 25 записів;
- `readers` — 7 записів;
- `loans` — 10 записів.

Кількість записів збігається з початковою базою SQLite.

### 4. Перевірка автоматичної генерації ID

Додано тестову книгу без зазначення `id`. PostgreSQL автоматично присвоїв їй ID = 26. Після перевірки тестовий запис видалено.

### 5. Перевірка зовнішнього ключа

Спроба додати позику з неіснуючим `book_id = 999` завершилася помилкою SQLSTATE 23503. Це підтверджує роботу зовнішнього ключа.
### 6. Контрольні запитання

1. PostgreSQL використовує клієнт-серверну архітектуру, а SQLite є вбудованою СУБД. Ієрархія PostgreSQL: кластер, база даних, схема, об'єкти.

2. `GENERATED ALWAYS AS IDENTITY` — стандартний механізм SQL для генерації ID. `SERIAL` — специфічне скорочення PostgreSQL.

3. `books` і `readers` створюються першими, оскільки `loans` посилається на них зовнішніми ключами.

4. Без синхронізації послідовності наступний ID може збігтися з наявним, що спричинить помилку первинного ключа.

5. pgAdmin — графічний інструмент керування PostgreSQL. Query Tool — SQL-редактор, подібний до SQL-редактора DB Browser for SQLite.

6. PostgreSQL автоматично перевіряє зовнішні ключі. `PRAGMA foreign_keys = ON` потрібна для SQLite, а не PostgreSQL.

### 7. Висновок

Під час практичної роботи виконано міграцію даних із SQLite до PostgreSQL. Створено таблиці, налаштовано ключі, імпортовано CSV-файли та синхронізовано послідовності IDENTITY. Перевірено автоматичну генерацію ID і роботу зовнішніх ключів. Кількість записів у PostgreSQL збігається з початковою базою SQLite.
